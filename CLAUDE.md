# Stage — monorepo guide for Claude

Stage is a private, encrypted XMTP messenger with multi-account support, group channels, free onchain names and avatars (`*.stage.base.eth` on Base, read like Basenames), and a ZeroDev smart-account wallet on Base (assets, balances, transfers, recovery phrase backup). The product bet is a privacy super app where **agents are contacts**.

It ships **one universal Expo app** (`apps/stage`) serving **android, ios, web and desktop** from the same React Native codebase (web via react-native-web), built on a framework-agnostic TS core (`packages/client`), a design-system kit (`packages/kit`), a Cloudflare Worker (`apps/proxy`) and the XMTP push server (`apps/push`). Tooling: **Bun 1.4.0** (exact, the only package manager — no npm/npx, no package-lock.json) + Turbo, **Node >=22**.

There is no separate web app: the Vue client (`apps/ui`) and the kit Vue renderer family were removed when `apps/stage` became universal. **The parity invariant is retired** — a screen exists once. The JSON widget dialect (`KitRenderer`/`ViewHost`, `WidgetNode`, node registry) is also retired — all UI, including chat message content, is direct kit JSX. The one exception is agent-sent content: frames and nodes carry A2UI v1.0 messages that the kit's `A2uiSurface` renders (see Kit below), never app UI. The ChatKit frame format is gone. Railgun / shielded transfers and the embedded Node host were removed in Sept 2026 — the wallet is public-only; do not reintroduce them. The wallet screen is the balance card (Send, Receive) plus the token list: the NFT and Activity tabs, the profile NFT view and their OpenSea/Etherscan clients were removed in Sept 2026. Token rows do not open anything: the token detail page was removed in Sept 2026. A profile page shows no tokens, the owner's own included: holdings appear only in the Wallet tab. The token list is exactly ETH then USDC on Base (`WALLET_ASSETS`), in that order, even at 0, for smart and key accounts alike: balances are fetched on Base only, the total is the sum of those two rows, and the send picker offers the same two with ETH as the default. `ASSETS` keeps the other chains' tokens only so transaction cards in chats can name and price them.

## Architecture

### Universal app (`apps/stage`)
- **One codebase, three platforms.** Web is react-native-web (`app.config.js` web `output: 'single'` — static SSG would execute native imports at build time). Platform divergence lives ONLY in Metro platform extensions: `x.ts` (native/default, typechecked) + `x.web.ts` (web override, identical export surface). A small `Platform.OS === 'web'` check is fine for feature gates.
- **Platform seams:** `platform/storage(.web).ts` (SecureStorage/AppStorage contracts in `platform/types.ts`), and the small `lib/xmtp.*.web.ts` family implementing the native modules' surfaces against `@xmtp/browser-sdk` (sdk/client/codecs/dbkeyFs/state/attachments/recover/foreground/wasm; `xmtp.types.ts` is SDK-neutral and shared by both). The SDK primitives live in ONE adapter pair, `xmtp.sdk(.web).ts`, typed by `XmtpSdk<Client, Conversation, Message>` in `xmtp.sdk.core.ts`: every conv/groups/identity/messages/resync/readSync/history/stream orchestration is a single SDK-neutral module over `sdk` (so `xmtp.conv.ts`, `xmtp.stream.ts`, ... have no `.web` twin), and a deliberate native/web difference belongs in the adapter, never in the orchestration. `xmtp.stream.ts` is the one global message stream (the foreground/push resync policy is the `xmtp.foreground(.web).ts` seam), the conversation and consent streams are ref-counted through `makeSharedSource`, and account switch/delete/reset, installations and client errors are `makeClientLifecycle` in `xmtp.client.core.ts` (unit-tested), with only the SDK build/open/revoke left in `xmtp.client(.web).ts`. Web variants cross-import each other with explicit `./xmtp.X.web` specifiers. Anything SDK-neutral lives once in a `*.core.ts` (`xmtp.sdk.core`, `xmtp.client.core`, `xmtp.state.core`, `xmtp.recover.core`, `xmtp.signing.core`, `cache.shared`) and both seams call it; never re-implement shared logic in both files, use `xmtpClient()` for the cached-or-create client, and type seam code against the SDK (`instanceof Group`/`Dm`, `consentState()`, …) rather than `as unknown as` shapes — a cast hid a web-only bug where `conversations.stream` took a callback the browser SDK never called. Components import messaging from the module that defines it (`lib/xmtp.conv`, `lib/xmtp.messages`, `modules/messaging/queries`, ...); there is no barrel. There is no web stub for native-only packages: `@xmtp/react-native-sdk` stays out of the web bundle because only the native seams value-import it (everything else uses `import type`), so keep it that way.
- **Web scroll architecture — the document scrolls, nothing else does.** `public/index.html` gives body `min-height: 100vh; overflow-x: hidden; overflow-y: scroll` (native window scrollbar, always visible; horizontal overflow from transforms such as the swipe-to-reply spring never becomes a scrollbar); every screen renders in normal flow. Two seams make that possible with the SAME screens as native: `lib/navigation(.web).tsx` (react-navigation stack/tabs natively; on web a flow navigator: the stack keeps every route mounted but hides inactive ones with `display: none` so nested navigator state survives a push/pop — unmounting the tabs reset them to Chats on back — while the tab navigator renders only the focused tab; no absolute-fill cards) and the scroll hosts in `components/layout/` — `ScreenScroll` (ScrollView natively, a plain View on web) and `VirtualList` (FlatList natively; on web TanStack Virtual with `scroll="window"` by default or `scroll="self"` inside the fixed channels pane, `anchor="end"` for the chat feed). Chrome floats over the flow via `webChrome.ts`: headers are `STICKY_TOP`/`STICKY_UNDER_CHROME`, the rail, sidebar, tab bar, band, conversation header and composer are `pinned*` (`position: fixed` on web, `absolute` natively), overlays use `viewportFill()`. The root `WebContentFrame` (in `app/_layout.tsx`) pads the document by `--stage-pane-left` (`paneWidth.ts`) when the split sidebar is showing; `useDocumentScrollRestore` restores `window.scrollY` per route. Never add `overflow: scroll` containers or `100vh`/`100vw` sizing to a screen; put content in flow and let the page grow.
- **Phones never show a scrollbar.** On a touch device (`pointer: coarse`) `public/index.html` hides every scrollbar on web, the window's included, so the always-visible window scrollbar above is a mouse and trackpad thing only. Natively `ScreenScroll`, `VirtualList` and the kit `Scroll`/`FlatList` hide scroll indicators by default; the kit keeps them on web, where react-native-web would otherwise hide desktop scrollbars too.
- **Main menu.** On web at 1100px and up (`useWebTabRail`) the left rail (`components/tabs/WebTabRail.tsx`) shows Chats, Board and Wallet, then the pages in `components/tabs/menuPages.ts`: Contacts, Dashboard, Storage and Inbox at `/contacts`, `/dashboard`, `/storage` and `/inbox`, beside the channels pane and with no back arrow. Smaller screens and native open them from Settings, More (Inbox only with an st.box mailbox), with a back arrow to `/settings`; Settings leaves them out where the rail shows them.
- **Env vars must be read as literal `process.env.EXPO_PUBLIC_X` member expressions** (pass them to `envString`/`envBaseUrl` in `lib/env.ts`) — dynamic `process.env[name]` defeats the Expo inliner on web.
- **Models are colocated with components:** presentation logic lives in pure `*.model.ts` files next to the component that consumes them (`components/ChannelRow.model.ts`, `components/settings/WalletSettings.model.ts`, ...). Framework-free — no React imports — and unit-tested in `test/` (`*.spec.ts`). Display helpers in `lib/format.ts`; platform effects (navigate/back/backTo/copy/toast/confirm/openUrl) go through `lib/capabilities.ts`.
- **UI composition — everything is direct kit JSX:** state hook -> colocated model -> kit components (shared chrome in `components/chrome/` — StackHeader (with a `wallet` variant)/EmptyState/RetryNotice — plus shared widgets in `components/widgets.tsx` and domain families like the settings rows in `components/settings/SettingsPage.tsx`). Chat message content (poll cards, media cards, link previews, voice/video, message bubbles) is JSX too, in `components/bubble/` and `components/composer/`.
- expo-router file routes in `app/`; `_layout.tsx` imports `lib/jsPolyfills` + `lib/cryptoShim` FIRST (order matters). Hand-rolled stores (`lib/storeCore.ts`, `lib/persistedStore.ts` over `platform/storage`) + react-query. App variants via `APP_VARIANT` (prod = Stage/stage.box, dev = dev.stage.box). "Metro" only ever means Expo's bundler here. The product, its domains, endpoints and every new identifier are Stage/stage.box; the handful of frozen legacy identifiers that keep an older string are listed in `docs/legacy-identifiers.md` and must not be renamed or extended.

### Shared core (`packages/client`)
- What belongs here: any logic that needs no React, React Native, Expo or XMTP SDK value import, no env read and no storage. Hooks, SDK calls, env and storage stay in `apps/stage`, which imports the logic.
- No build step; the subpath exports in `package.json` are the public API (there is no root barrel). Pure functions + plain interfaces, no classes/default exports. Boundary validation via `validate.ts` (zod). Always decode XMTP content WITH a zod schema (`decodeJsonContent(bytes, schema)`).
- **Frames on the wire:** `stage.box/frame:2.0` (`xmtp/frame.ts`, `xmtp/frame.schema.ts`) carries `{ title?, description?, messages, start?, source? }`, where `messages` are A2UI v1.0 `createSurface`/`updateComponents`/`updateDataModel`/`deleteSurface` messages (at most 200 messages, 64K characters, 500 components). Each surface is a screen: the first (or `start`) shows, and the Kit catalog functions `openSurface`/`closeSurface` move between them on a back stack (`components/frame/frameStack.ts`, keyed by message id and shared by the bubble and the page); the top nav shows the surface's first `Title` (else the frame's title) and goes back a screen, and to the chat only from the first. `1.0` ChatKit frames no longer decode and show their fallback text. The app renders a frame with `components/frame/FrameView.tsx` (the shared session client from `lib/frameSession.ts` + `A2uiSurface`, media `https://` only via `frameMediaUrl`, an error boundary and a notice for a missing surface or a tree over the render limits). The feed shows the frame itself, live (`components/frame/FramePreview.tsx`): its controls work in place, and the bubble shows a small bar with a back arrow and the screen title on a later screen. It is as large as an image at most (`ATTACHMENT_MAX_WIDTH` x `ATTACHMENT_MAX_HEIGHT`); taller content scrolls inside it, with a fade while more is below. Android gets no nested scrolling there (`nestedScrollEnabled` would chain the overscroll backwards into the inverted feed). A full screen button in the top-right corner (on hover with a mouse, always on touch and in the screen bar) opens the frame page on the same screen. Every chat frame has a three-dot menu above it (`components/frame/FrameMenu.tsx`, with the node's host on the left for a frame with a node), and the frame page has the same menu in its top nav: Add to dashboard, plus Refresh and Copy link for a frame with a node. The title, derived from the start surface when missing (`frameSummaryOf`), names it in the chat list, and `/frame?convId=&id=` (`app/(conv)/frame.tsx`, a split route) shows it in the main pane with only the top nav and the page gutter. An A2UI event action sends `stage.box/frameAction:2.0` `{ frameId, action: <A2UI action event>, label?, dataModel? }` to the same conversation (`label` is the event's `userMessage` or the tapped button's text; `dataModel` only when the surface sets `sendDataModel`; the frame page then goes back to the chat, the bubble stays as it is); the feed shows it as a small muted line with a pointer icon, `Tapped "<label>"` (`Tapped <name>` without a label), under a quote of its frame, the chat list previews it as the same text, and other clients see `Frame action: <name> <context>`. A frame that names a node with `source` (see `NODES.md`) sends every renderer message to that node instead (`action`, `callAgentFunction`, `rendererFunctionResponse`, `error`), signed, with the renderer capabilities in `metadata.a2uiRendererCapabilities` and the `Stage-A2UI-Capabilities` header, and applies every A2UI message it answers (surface messages, `agentFunctionResponse`, `callRendererFunction`) in place on this device only. Each shown frame has ONE live A2UI client in `lib/frameSession.ts`, keyed like the frame (`<epoch>:<messageId>` for chat frames, `live:<widgetId>` for dashboard widgets) and shared by every view of it: replies go into that client, so local edits and settled agent calls survive, and only a reply with surface messages re-snapshots the stored frame (`lib/liveFrame.ts`, in memory) with `snapshotOfClient`; the client is rebuilt only when a different frame arrives (a reload). Node replies stream: with `onMessage` the protocol reads a `application/jsonl` or `x-ndjson` body line by line (other bodies whole) and delivers each validated message at once (`packages/client/src/nodes/protocol.ts`; a plain JSON reply is validated whole before any message is applied); `streamInto` applies each one to the session and the new frame reaches the screen mid-reply. A load fills a separate loading client (keyed by a token so a stale stream writes nothing) that replaces the shown one only once it renders, so a frame never blanks. Every view of a frame registers a host on its session (a stack, so closing the frame page leaves the bubble working); a host accepts a message only when the frame is not locked and, for a chat frame with a node, only taps until the user taps or refreshes it (`engageFrameSession`), so rendering a frame never contacts its node. Held messages wait in a capped queue, and a frame with no node answers `callAgentFunction` locally with `UNKNOWN_FUNCTION`, so nothing waits forever. Only a tap or Refresh in its three-dot menu calls the node, never a render; such a frame stays read only and its menu has no Refresh until the chat is known to be accepted (`frameLocked`). The frame page and dashboard frame widgets show a message only from the chat they name (`lib/frameMessage.ts`; a DM with the same peer counts). Actions are disabled until the conversation is accepted. Agents on metro.box send frames with the `frame` field of the XMTP `send` tool, which must carry this A2UI shape.
- Domains: `xmtp` (codecs incl. the `jsonCodecs` table, humanize, builders, line routing, consent, and the orchestration cores: `channelsFilter`, `channelsCache` incl. `applyInbound`, `summarizeRow`, `clientErrors`, `envelope`, `groups`, `reactions`, the push cores `pushRegistration` and `pushSenderFilter` with their `sendTiming` phases, plus `messageBody` and `channelLinks` parsing), `accounts`+`zerodev` (ECDSA Kernel accounts, HD derivation, recovery), `wallet` (incl. `txSimulate`, `txConfirm`, `txWording`, `txDecode`, `prices`), `api` (ens, `defillama` prices, `github` link detection), `identity` (Basenames + `stageNames` read/write and `randomUsername`, `onchainProfile`, `peerProfiles`), `profile/avatar` (stamp + IPFS avatar URLs), `profile/setup` (incl. the `runProfileSetup` runner), `abortable`, `embed/routing/image/text` (incl. `embed/cardLinks`, `text/codeBlocks`), `x402` (challenge and `x402/payment`).
- Names and avatars come from Base only (Basenames or `*.stage.base.eth` issued by the proxy; issued names may lack a forward `addr` record, so resolution accepts registry ownership and falls back to `/names/resolve`). Mainnet ENS is not consulted. Usernames are `a-z0-9` with single inner hyphens, 6+ chars, validated in the client AND in the Worker. A `*.stage.base.eth` name is a native Stage username: it is displayed as `@label` everywhere (`displayHandle`, applied inside `getPeerName`), while routing and resolution keep the full onchain name. A bare label typed into the channels search resolves the same way (`peopleLookup` -> `resolveHandleToAddress`), so `tony123` finds `tony123.stage.base.eth`.
- **Kernel key model (money path).** Smart accounts are ZeroDev Kernel v3.1 on Base (EntryPoint 0.7). The recovery-phrase ECDSA validator is the root (sudo) and sole wallet validator. Messages, typed data and transactions all use it. `kernelClientForRecord` derives the owner from the record's phrase and HD index, then reuses `createEcdsaKernel` with the existing address. Creation, restore and Link a device use the same account derivation. Native device-bound secret storage and the device-auth sentinel for explicit export and transfer remain separate from signing.
- **Deleting a direct chat** (row menu, DMs only; channels keep "Leave channel") writes a `clearState` snapshot (peer address -> deleted-at ms, merged by max per peer) to the private `stage.sync:` group beside `readState`/`pinState`, so every device hides it, and sets the conversation's consent to unknown ("Delete and block" sets denied). A row stays hidden until a real message newer than the deletion arrives (`isRowCleared` on `lastBubbleTs`: reactions and read receipts never revive it), the feed shows only messages after the deletion, and the unread badge skips hidden rows. XMTP cannot leave or delete a DM, so this is the whole mechanism.
- **Deleting a message** (message menu, not channel updates) uses XMTP's XIP-76 `xmtp.org/deleteMessage:1.0`, a delete for everyone. Anyone deletes their own messages; in a channel a super admin also deletes other people's messages (plain admins cannot, XIP-76 allows only super admins; DMs are own messages only), with a confirm that says so. Native calls `deleteMessage` on the message's own conversation; the browser SDK has no delete call, so web sends the hand-encoded content from `packages/client/src/xmtp/deleteMessage.ts` with `shouldPush: false`. XMTP deletes only the content types it knows (text, markdown, reply, attachments, transaction reference, wallet send calls): libxmtp refuses any other type when sending the delete and ignores such deletes when they arrive. So for Stage and metro types (frames, frame actions, polls, signature requests) `xmtpDeleteMessage` sends Stage's own `stage.box/deleteRequest:1.0` `{ messageId }` instead (`isXmtpDeletableType` decides, no push). Both SDKs return it as a normal message, and the envelope maps it to the same delete request, so `deletedMessages` applies it with the same sender or super admin check. Reads differ: the web SDK returns a `deletedMessage` placeholder in place of the original (it already checks sender or super admin, and says which in `deletedBy`), while native reads raw messages, so the delete request rows stay in the feed and `deletedMessages` (`xmtp/deletions.ts`) applies only those sent by the original sender or by a current member who is a super admin of the channel now (`superAdminInboxIds` over the `useChannelRoles` data; libxmtp checks the role when the delete arrives instead). The deletion streams (`sdk.streamDeletions`) update open feeds live. The sending web installation keeps the original, so `lib/ownDeletes.ts` hides deletes made on this device locally (per account, rolled back if the send fails). Deleted messages render as a muted "Message deleted" row ("Message deleted by an admin" when a super admin deleted someone else's message) with no content or reactions, reply quotes, search and the chat list preview follow it, and other apps may still show the original.

### Kit (`packages/kit`)
- **Kit is A2UI first, ChatKit for the extras.** The components are the [A2UI v1.0](https://a2ui.org) basic catalog under their A2UI names, props, literal unions and defaults (`Text`, `Image`, `Icon`, `Video`, `AudioPlayer`, `Row`, `Column`, `List`, `Card`, `Tabs`, `Modal`, `Divider`, `Button`, `TextField`, `CheckBox`, `ChoicePicker`, `Slider`, `DateTimeInput`). Where A2UI is silent, extra props and the few extra components (`Title`, `Badge`, `ListView`, `Spinner`, `QrCode`, `Chart`, `DropdownMenu`, `Tooltip`, ...) keep [OpenAI ChatKit](https://openai.github.io/chatkit-js/)'s names. Clashes resolve to A2UI: `weight` is flex grow on every component, so font weight is `fontWeight`; Button `variant` takes A2UI's `default | primary | borderless` (default `default`, a secondary solid) or a fill `solid | soft | outline | ghost` used with `color`. JSX adaptations: child ids become React children, `action` is `onPress`, bound values are `value` + `onChange`. Never invent a component or a token value, and never write a raw literal where a token exists (`FONT_SIZE.*`, `fontName.*`, `semanticColors`, `RADIUS_SCALE`). The theme stays ChatKit's `ThemeOption` surface 1:1 (A2UI leaves branding to the renderer); OpenAI does not publish ChatKit's colour maths, so `theme-derive.ts` implements the documented semantics itself — defaults are lossless and guarded by tests. See `packages/kit/README.md` for the tables.
- Plain design-system component library: ONE component family (`src/react-native/*`, renders on web via RNW) + shared style cores (`text.styles.ts`, `button.styles.ts`, `control.styles.ts`, `layout.ts` surfaces, `badge.ts`, `icons.ts`, `tokens.ts` incl. the `Scheme`/`Color` helpers). Consumed via subpath exports (`@stage-labs/kit/tokens`, `@stage-labs/kit/react-native/button`, ...).
- Theming: preference contract (`theme.ts`), runtime context (`react-native/theme-context.tsx`), custom-palette deriver (`theme-derive.ts`, LEGACY short-circuit guarded by tests).
- **A2UI (`src/a2ui/`, pure TS; renderer in `react-native/a2ui-*.tsx`)** implements A2UI v1.0 (candidate) with the official schemas vendored in `src/a2ui/schemas/` and passes the official conformance suite (`test/a2ui/cases`). `createA2uiClient` takes every agent message (JSON, JSONL, lists), validates against the catalogs (invalid components are dropped with `VALIDATION_FAILED`), evaluates bindings, `formatString`, `@index` and the basic functions with `allowedCallers`/`requiresUserActivation`, and sends `action`/`error`/function messages with `sendDataModel` metadata. The Stage Kit catalog (`https://kit.stage.box/a2ui/v1_0/catalog.json`, `kit-catalog.ts`, published by the gallery build) inherits the basic catalog and adds the Kit props, tokens, icon names, extra components (`Chart` and `DropdownMenu` included; a bound `Modal` `open` and `accessibility.label` hover tooltips on icon-only controls need no new component) and the `openSurface`/`closeSurface` screen functions (the client's `navigate` option). Every Kit style prop also takes a data binding or a function call, and `Row`/`Column` take sizes (pixels or a percentage), per-side `padding` and `border`; the renderer keeps only Kit tokens and hex colours, pixel or percentage sizes and known padding sides from the data. Inputs only write to the data model while typing, as the spec says: a Button action whose context references them sends their values, and a single-line Kit `TextField` `action` runs on Enter (a submit, like a Button press). `A2uiSurface` renders a surface (`disabled`, `mediaUrl` filter, `fallback` for a tree that fails the render limits: cycles, depth 32, 2000 nodes; `Video`/`AudioPlayer` only with `renderers={MEDIA_RENDERERS}` from `react-native/a2ui-media`, which `FrameView` passes, because they load Expo and plain react-native-web hosts such as the Dashboard have no Expo runtime), `useA2uiClient` builds a client for a message list, and `a2uiSnapshot`/`snapshotOfClient` compact a message log. Text markdown follows A2UI: no HTML, images or links. Drag and drop is `react-native/sortable` (`SortableScope`/`SortableList`/`SortableItem`/`SortableHandle`, gesture-handler on the JS thread, pure maths in `src/sortable.ts`; by default a floating copy follows the pointer while a dimmed copy takes real space where the item lands (`preview`; `line` marks the place with a line instead, `placeAt` lets a sorted list say where an item really lands, and a pointer outside every list targets the nearest list across it), `indicator="shift"` for in-place sliding within one list, `follows` for items that move with another, `useSortableTarget` for custom feedback, and positions from `itemIds` so virtualized lists work; gesture callbacks get their own copies of captured variables, so shared drag state lives in the coordinator); the Kit catalog `List` uses it with `sortable`, `group`, `listId`, `itemKey`, a `move` binding and a standard `action`, and the Stage board (cards between columns, landing at their sorted place, columns by their header, both in `preview` mode) and the chat list (`components/home/listDrag.tsx`: pinned rows and project sections in `shift` mode, rows into another project in `follow` mode with the target project highlighted, three nested lists around the virtualized list) are built on it. `src/a2ui/**` and the root `src/*.ts` style cores import no React, React Native or Expo module, not even types (a `no-restricted-imports` override in `.oxlintrc.json`; `control.styles.ts` and `glyph.ts` are exempt and must stay out of the A2UI graph), so servers can import the client and the catalog. Agent functions follow the spec: a function the renderer does not implement goes to the agent as `callAgentFunction`; the Kit catalog lets agents call the basic formatting functions, while `openSurface`/`closeSurface` need a tap and stay renderer only. The ChatKit `Frame` renderer is gone.
- **Storybook = `packages/kit/gallery/`** (own Vite shell built from kit components, react-native-web alias in `vite.config.ts`; stories in `stories/*.stories.tsx` in Storybook CSF shape with `args`/`argTypes`): every component gets a `Controls` story listing all props with literal unions as selects, plus matrix stories for variant axes. Stories import kit sources only, never `apps/stage`. New component => new story file; knip treats `stories/*.stories.tsx` as entries. No Storybook/Ladle dependency; keep it that way.

## Conventions

- **Commits:** Conventional Commits `type(scope): subject (#NNN)`, lowercase imperative. Trailer required: `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`. Commit/push only when asked; branch first if on `main`.
- **NO COMMENTS IN CODE** — `comments/no-comments` bans non-directive comments across `.ts/.tsx/.js` including config files AND test files (the JS-file and test overrides in `.oxlintrc.json` enable it too). Express intent in names/types. Markdown is exempt.
- **NO EM DASH (`—`) anywhere in source or copy** — `text/no-em-dash` (same overrides) fails lint on any string literal, template or JSX text containing it. Write two sentences, or use a comma or colon; empty-value placeholders use a plain `-`.
- **No TS escape hatches:** no-explicit-any, no-non-null-assertion, ban-ts-comment are errors; `noUncheckedIndexedAccess` is on — null-guard, never assert.
- **Single quotes**; max 400 lines/file, 100 lines/function, cyclomatic complexity <= 10.
- **Errors:** no empty `catch {}` and no `.catch(() => undefined/null/false/[]/{})` in `apps/stage` (`stage/no-silent-catch`). Use `lib/errorPolicy`: `ignore`/`ignored`/`attempt` with a `BestEffort` reason for true best-effort work (cleanup, cache, probe, ui, optional), `report`/`reported`/`recover` to log and continue (redacts key material). Never map a failed storage READ to "absent" when a write may follow; let it throw. `capabilities.toast` works on every platform (`ToastAndroid` on Android, `ToastHost` elsewhere). `@xmtp/react-native-sdk` may only be value-imported by a native seam `x.ts` with an `x.web.ts` sibling (`stage/native-only-in-seams`).
- **Page gutter:** horizontal page padding is `PAGE_GUTTER` (18px, `components/layout/gutter.ts`); never hard-code 12/16/24 for a screen edge. `LIST_TOP_GAP` (14px, same file) is the vertical padding of the sidebar filter chips and the top padding of the Contacts list, so Contacts starts as far under its topnav as the chat list starts under the chips. Dropdown menus, tooltips and modals render the kit `DropdownMenu`/`Tooltip`/`Modal` (the app only positions them; `AppModal` picks centered vs bottom sheet; where a menu cannot anchor, `AnchoredMenu` shows the same rows in the kit `DropdownMenuSheet`; forms such as Edit profile are modals, not routes. New chat is a page, not a modal: on desktop the homepage `/` is `components/home/NewChatScreen.tsx` (people picked above the composer, a new channel with them is created only on send, even for one person; send locks the composer, the channel opens as soon as it exists and the send starts at once (`composer/sendRun.ts`) and is handed to that channel's composer (`composer/handoff.ts`), which shows it as sending and settles it like any send), phones open the same screen at `/new`, and so does desktop in board view, where it opens beside the board like a channel); icon buttons tint to the link colour on hover via `components/hover.tsx`, and web tooltips on arbitrary controls go through `HoverTooltip`. A `HoverTooltip` `shortcut` shows after the label as a `components/Kbd` key cap, through the kit `Tooltip` `trailing` slot.
- **External links are real links:** a URL the user can open is spread with `bubbleLinkProps(url, openInBubbleLink)` (`components/bubble/linkProps(.web).ts`) on the kit `Pressable`, `Text` or `Button`. On web that is an `<a href>` with `target="_blank"` and `rel="noopener noreferrer"` (middle-click, Ctrl or Cmd click, hover URL, browser link menu), stage.box links still route in the app, and natively it is a plain press. Never a `Pressable` with `capabilities.openUrl` or `Linking.openURL` for a link. The desktop shell opens them in the system browser.
- **Forms:** every text input except the message composer goes through `components/FormField` (filled with the border colour, no border, radius 4, label inside above the value). Never style a kit `TextField` inline in a screen.
- **Labels are the kit `Badge`** (fully rounded by default): channel labels in rows, cards, the intro and the sidebar, filter chips, member roles and the x402 tag. `components/LabelChip` wraps it for label chips with icons and `CountTag` for counts. `LabelChip` picks a Badge `size` (`md` in the sidebar filters, `lg` elsewhere) and draws its text with the props the Badge passes to a function child, so the app sets no font size for it. Keep a label's look with `Badge` props (`size`, `background`, `color`, `textSize`, `weight`, `style`), never a hand-rolled pill `Row`.
- **Security invariants:** the keyring (`lib/zerodev/keyring.ts`) is the only importer of private-key/mnemonic primitives (`stage/no-keyring-bypass`), every `secureStorage` get/set in the keyring and `xmtp.dbkey.ts` passes a `DeviceBoundAccessOptions` const, and `lib/cryptoShim.ts` never touches `Math.random` — all lint rules: `stage/*` in `apps/stage/oxlint-plugin.mjs`, the storage and CSPRNG selectors in the root `.oxlintrc.json`. Never print operator or private keys; secrets reach CI only as GitHub secrets and the Worker only via `wrangler secret`.
- **Kit-only UI:** build screens from kit primitives in JSX fed by colocated `*.model.ts` models, not raw RN style objects; `usePalette`/`useEffectiveColorScheme` for the few native-styled shells.
- **No circular deps** (madge) and **no unused files/deps/exports** (knip). New workspace => `stage.config.js` entry + `madge.roots`.
- Invariants about source shape (which module may import a secret primitive, that every secure write is device-bound, no `Math.random` in the crypto shim) are lint rules (`apps/stage/oxlint-plugin.mjs`, the root `.oxlintrc.json`), never tests that `readFileSync` a source file and `toContain` a line — those break on every refactor and catch nothing.
- Snapshot-bearing test files are `*.spec.ts` (bun writes `*.test.ts.snap` files that the `**/*.test.*` lint glob would pick up and always fail). The remaining snapshot suites live in `packages/kit/test/` (button/layout/theme-derive); `apps/stage/test/` is pure-model tests only.

`.github/workflows/ci.yml`: **lint -> typecheck -> knip -> madge -> build -> test** (Bun 1.4.0, frozen lockfile).

## Gotchas / footguns

- **Netlify config is `apps/stage/netlify.toml`, NEVER at the repo root.** The Stage site's base directory is `apps/stage` (set in the Netlify UI), so Netlify reads that file; a root toml applies to every site built from this repo and hijacked the kit gallery site. The toml sets the command (`bun install && bun run build:web`), publish (`dist`), `BUN_VERSION`, `NODE_VERSION`, the secrets-scan exemption for the public Firebase client key, the COOP/COEP headers, the SPA redirect and the `ignore` rule: Netlify alone skips a build when nothing changed in the base directory, so the rule builds whenever `apps/stage`, `packages/`, `patches/` or the root `package.json`/`bun.lock`/`bunfig.toml` changed (a kit-only push once never reached stage.box). Kit gallery site: base `packages/kit`, configured in the UI only (command `bun install && bun run storybook:build`, publish `packages/kit/build`, env `BUN_VERSION`; Node from `packages/kit/.nvmrc`). Headers: COOP same-origin + **COEP credentialless** (deliberate — keeps SharedArrayBuffer for XMTP wasm while cross-origin avatars/IPFS load). Don't change to require-corp.
- **The web export is tree shaken.** `EXPO_UNSTABLE_TREE_SHAKING` and `EXPO_UNSTABLE_METRO_OPTIMIZE_GRAPH` are set in `apps/stage/netlify.toml` and in the desktop `scripts/export-ui.mjs`, never in the `build:web` script (package.json scripts are an Expo fingerprint input). Without the `@expo/metro-config` patch to `collect-dependencies.js`, tree shaking drops the two XMTP web workers (`new Worker(new URL(...))` in `@xmtp/browser-sdk`): check that the export still lists the `client` and `opfs` bundles after an Expo upgrade. The web QR reader (`jsqr`, only where the browser has no `BarcodeDetector`) and Firebase messaging (`lib/firebaseWeb.ts`, on push registration) load as async chunks on first use.
- Native module changes (e.g. `modules/stage-pill`) need a fresh dev-client build; a JS reload is not enough.
- **Attachments are encrypted when picked and uploaded when sent.** `makeAttachmentPrep` (`lib/xmtp.attachmentPrep.core.ts`, used by both `xmtp.attachments(.web).ts`) keeps one job per file: the composer calls `prepareAttachments` on pick (local only, nothing leaves the device), `uploadAttachments` when send starts (new chat: while the channel is created), and the send awaits the same jobs. A failed job is dropped so the next try runs it again; a sent or removed file is forgotten.
- **Main-thread XMTP wasm is not single-flight.** Every browser-sdk helper that runs on the page instead of in the worker (static `Client.canMessage`/`revokeInstallations`, `encryptAttachment`/`decryptAttachment`, `encodeText`) lazily inits the wasm, and two cold calls at once instantiate it twice: the first call's pending closures then hit the second instance and throw `closure invoked recursively or after being dropped` (and hang). Wrap every such call in `withMainThreadWasm` (`lib/xmtp.wasm.web.ts`).
- **Mobile releases are version-driven** (the `version` in `apps/stage/app.config.js` triggers `release-mobile.yml`: EAS Build + EAS Submit for Play and TestFlight, see `docs/mobile-release.md`). Account identifiers are injected at build time, never committed to `eas.json`. EAS free tier has a monthly build cap. Every push to every branch publishes a JS-OTA dev-client preview (`pr-preview.yml`; the "Preview" commit status carries the deep link).
- `@stage-labs/config` publishes via `publish-config.yml` under the `beta` dist-tag; bump its version first (the next beta prerelease, never a stable version). It has no ESLint or Vue presets since 0.1.0-beta.3.
- **Publishing is the one npm step.** `publish-kit.yml` and `publish-config.yml` build the tarball with `bun pm pack` (it rewrites `workspace:*` ranges) and publish it with `npm publish --provenance` on Node 24, because `bun publish` has no provenance or npm trusted publishing (GitHub OIDC, `id-token: write`). npm uses the OIDC trusted publisher configured for each package on npmjs.com and falls back to the `NPM_TOKEN` secret until then; once the trusted publisher works, disallow token publishing on npmjs.com and delete the secret. Releases stay on the `beta` dist-tag.
- The ECDSA Kernel tests (`ecdsaKernel`) never touch the network: `apps/stage/test/recordedBaseRpc.ts` replays the Base RPC answers stored in `apps/stage/test/fixtures/base-rpc.json`. A request with no stored answer fails the test. After a ZeroDev or viem upgrade changes a request, record new answers from `apps/stage` with `STAGE_RPC_RECORD=1 bun test test/ecdsaKernel.test.ts` (not through turbo, which drops the variable). Missing answers are fetched from Base (`EXPO_PUBLIC_ZERODEV_RPC` if set, else mainnet.base.org) and written to the fixture. Only results and `execution reverted` errors are stored, never a transient RPC error. Commit the fixture.
- Button taxonomy: `variant` is A2UI's `default | primary | borderless` (default `default`) or a fill `solid | soft | outline | ghost` with `color`. The legacy `secondary/danger` variants are gone — don't reintroduce them.
- `theme.ts` setters call the persist helper; don't mutate display state directly.
- **Typecheck is tsgo** (`@typescript/native-preview`, pinned exactly), about 8x faster than `tsc`. `typescript` 5.9 stays for the tools that load its API (knip, Expo) and for `bun run typecheck:tsc`. TypeScript 7 gives `ESNext` more APIs and defaults `types` to `[]`, so the shared presets pin both for the two compilers: `lib` comes from `packages/config/tsconfig/lib.json` (ES2024 plus the ESNext parts both compilers declare the same way, so no Temporal, `RegExp.escape`, `Uint8Array` hex/base64, `Map.getOrInsert` or Set methods) and `base.json` sets `types: []`. List any global types a project needs in its own `types`.
- **Lint is oxlint**, pinned exactly (`oxlint`, `oxlint-tsgolint`). The type-aware rules run in the platform binary that `oxlint-tsgolint` pulls in as an optional dependency, so keep those entries in `bun.lock` (CI needs `@oxlint/binding-linux-x64-gnu` and `@oxlint-tsgolint/linux-x64`). `eslint` stays: the `core` JS plugin wraps ESLint's `no-restricted-syntax` and `quotes`. Not enabled on purpose: `prefer-optional-chain` and the react-hooks `config`/`gating` rules. The React Hooks rules cover only the React Compiler files, listed in `apps/stage/react-compiler-sources.cjs` and again in the react override of `.oxlintrc.json`: change both together.
